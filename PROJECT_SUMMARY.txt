  1. PROJECT OVERVIEW
================================================================================

TITLE
  MalayalamCyberCon: A Dataset and Classifier for Detecting Conflict and
  Cyberbullying in Manglish YouTube Comment Threads

PROBLEM STATEMENT
  Malayalam speakers on YouTube increasingly write in "Manglish" — Malayalam
  language typed in Roman script, often code-mixed with English. This informal
  register is almost entirely absent from existing NLP datasets. Toxic content
  (insults, slurs, threats, sexual harassment, political hate speech) in this
  register goes undetected by current moderation tools.

OBJECTIVE
  1. Build the first labeled dataset of Manglish YouTube comment threads
     annotated for conflict and cyberbullying.
  2. Fine-tune a multilingual transformer (MuRIL) to classify threads along
     four dimensions: conflict presence, severity, type, and target.
  3. Release the annotation pipeline and training code as open tooling.

LANGUAGE / DOMAIN
  - Language: Manglish (Malayalam in Roman script) + code-mixed English
  - Domain: Malayalam YouTube comment sections (movies, celebrities, reality TV,
    politics, food channels)
  - Platform: YouTube (comments scraped via YouTube Data API v3)

THREAD STRUCTURE
  Each thread = a chain of ≥2 YouTube comments on the same root comment.
  A "target message" is identified — the final or most salient comment —
  and that message is what the annotator labels.

  CSV format:
    thread_id, video_id, num_messages, thread_text, target_message,
    label_conflict, label_severity, label_type, label_target, notes

ANNOTATION SCHEMA
  label_conflict   : 0 = no conflict | 1 = conflict present
  label_severity   : 1 = mild  |  2 = moderate  |  3 = severe
                     (blank if conflict = 0)
  label_type       : 1 = personal attack
                     2 = political / communal
                     3 = sexual / gendered
                     4 = explicit threat
                     (comma-separated multi-label allowed, e.g. "1,3")
                     (blank if conflict = 0)
  label_target     : 1 = another commenter
                     2 = creator or public figure
                     3 = community / group
                     (blank if conflict = 0)
  notes            : free-text (sarcasm, ambiguity flags, etc.)

ANNOTATION GUIDELINES
  Full guide : data/annotations/ANNOTATION_GUIDE.txt
  Key rules  :
    - Criticising a film ≠ conflict; attacking a person = conflict
    - Slurs/sexual content/threats = severity 3 regardless of context
    - Playful banter ≠ conflict even if slightly rude
    - If conflict=0 leave all sub-labels blank (do NOT write 0)

================================================================================
  3. MODEL
================================================================================

BASE MODEL
  google/muril-base-cased
  - 12 transformer layers, 768 hidden dim, 12 attention heads
  - Vocab: 197,285 tokens (covers Malayalam, Hindi, Bengali + 15 Indian langs)
  - Pre-trained on Wikipedia + Common Crawl for 17 Indian languages
  - Chosen over xlm-roberta-base because MuRIL was specifically trained on
    Indian language text including transliterated Manglish content

  Rationale over other models:
    xlm-roberta-base  : trained mostly on Wikipedia, poor Manglish coverage
    IndicBERT         : no Roman-script Malayalam in training
    MuRIL-base-cased  : best fit — explicitly covers transliterated Indian langs

ARCHITECTURE
  Three separate fine-tuned classifiers (one per sub-task):

  CONFLICT MODEL
    Type      : BertForSequenceClassification (2 labels)
    Input     : full thread_text (all messages concatenated)
    Output    : P(no_conflict), P(conflict)
    Loss      : Weighted CrossEntropyLoss
    Labels    : 0 = no conflict, 1 = conflict

  SEVERITY MODEL
    Type      : BertForSequenceClassification (4 labels)
    Input     : thread_text (conflict=1 rows only)
    Output    : logits for [none, mild, moderate, severe]
    Loss      : Weighted CrossEntropyLoss (weight[0]=0 since class 0 not present)
    Labels    : 0 = none (padded), 1 = mild, 2 = moderate, 3 = severe

  TYPE MODEL
    Type      : BertForSequenceClassification (4 labels, multi-label)
    Input     : thread_text (conflict=1 rows only)
    Output    : sigmoid probabilities for each type
    Loss      : BCEWithLogitsLoss with per-class pos_weight
    Labels    : multi-hot [personal, political, sexual/gendered, threat]
    Threshold : 0.5 (if no class exceeds 0.5, highest prob class is taken)

CLASS IMBALANCE HANDLING
  WeightedTrainer (custom subclass of HuggingFace Trainer):
    - Conflict : compute_class_weight("balanced") → CE weights
    - Severity : compute_class_weight("balanced") + pad weight[0]=0 → CE weights
    - Type     : pos_weight[i] = neg_count[i] / pos_count[i] → BCE pos_weight
  Class weights are computed from the TRAINING SPLIT only (no leakage).

TRAINING HYPERPARAMETERS
  Epochs         : 5
  Batch size     : 16 (per device)
  Learning rate  : 2e-5
  Warmup ratio   : 0.1
  Weight decay   : 0.01
  Max token len  : 256
  Optimizer      : AdamW (HuggingFace default)
  Precision      : fp16 (on GPU)
  Early stopping : EarlyStoppingCallback(patience=2)  [where checkpoints used]
  Best model     : tracked in-memory via BestModelInMemory callback
                   (to avoid Kaggle disk-space issues)

TRAINING INFRASTRUCTURE
  Local (dry-run)  : CPU, Windows 11, Python 3.11
  Production       : Kaggle Notebook, GPU T4 x2, Python 3.12
  HuggingFace v    : transformers 5.0.0 (Kaggle), 4.x (local)

EVALUATION METRICS
  Primary   : macro F1 (used for model selection and early stopping)
  Secondary : accuracy, MAE (severity only)
  Conflict  : also Matthews Correlation Coefficient (MCC)
  Type      : exact-match accuracy + per-class F1 (multi-label)

================================================================================
  6. KEY DESIGN DECISIONS & RATIONALE
================================================================================

WHY THREAD-LEVEL (not comment-level) ANNOTATION
  Conflict in Manglish comments is often contextual — a reply that looks
  innocent in isolation becomes a targeted attack when read with the parent
  comment. Thread-level framing captures this better and matches how real
  moderation decisions are made.

WHY MULTI-TASK (not single model)
  Severity and type are only meaningful when conflict=1. Training separate
  models avoids polluting the conflict signal with severity/type objectives
  and allows independent deployment (e.g., use only conflict model for
  lightweight filtering, add severity for escalation routing).

WHY WEIGHTED LOSS (not oversampling)
  Oversampling (SMOTE) on text data with a transformer tokenizer is complex
  and can introduce artefacts. Weighted CE/BCE loss directly addresses
  class imbalance without modifying the data distribution, and is naturally
  compatible with HuggingFace Trainer.

WHY MULTI-HOT FOR TYPE (not single-label)
  A single comment can be simultaneously personal AND political AND sexual.
  Forcing a single label would lose this information and reduce the utility
  of the type classifier for fine-grained moderation policies.

WHY MuRIL OVER XLM-RoBERTa
  MuRIL was trained on 17 Indian languages including transliterated (Roman
  script) variants of Malayalam. XLM-RoBERTa's training corpus is Wikipedia-
  dominant and has minimal Manglish content. MuRIL's tokenizer also has a
  larger vocabulary (197k vs 250k for XLM-R but better Indian coverage).
